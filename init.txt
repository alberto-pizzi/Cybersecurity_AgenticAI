SecOps FastMCP - guida operativa
===============================

AMBIENTE
--------
Apri il terminale nella radice del progetto:
  Set-Location "<PROJECT_ROOT>"

Usa soltanto target tuoi o esplicitamente autorizzati. Per un target remoto
aggiungi --authorized e mantieni il Cookie header tra virgolette.

MCP
---
Un solo server FastMCP (`servers/secopsServer.py`) espone l'intero catalogo su
http://127.0.0.1:8100/mcp. I moduli dei singoli tool sono importati come componenti e
non aprono listener propri. Deterministic e Agentic condividono endpoint, registry, selector
e contratti MCP. Non sono previsti trasporti MCP alternativi.

1. INIZIALIZZAZIONE
------------------
Preparazione completa consigliata (default AI = tutti e tre):
python .\initScript.py --with-lab

Se NON specifichi ne' --prepare-ai ne' --agentic-model, --with-lab prepara:
  - Ollama + llama3.1:8b
  - Ollama + qwen2.5:7b
  - accesso Snap4City + llama4-agentic-inference
Snap4City e' remoto: non viene scaricato; l'initializer autentica e verifica che l'endpoint risponda.
I comandi Agentic stampati alla fine usano Snap4City per default.

Preparare un solo backend/model:
python .\initScript.py --with-lab --prepare-ai snap4city
python .\initScript.py --with-lab --prepare-ai llama
python .\initScript.py --with-lab --prepare-ai qwen

Quando viene preparato un solo backend, quel backend viene usato anche per --run agentic e per i comandi Agentic stampati.
Se specifichi --agentic-model SENZA --prepare-ai, l'initializer prepara automaticamente solo quel modello:
python .\initScript.py --with-lab --agentic-model llama
python .\initScript.py --with-lab --agentic-model qwen --run agentic --mode balanced
python .\initScript.py --with-lab --agentic-model snap4city --run agentic --mode balanced

Se specifichi ENTRAMBI, devono essere coerenti:
  OK:    --prepare-ai all --agentic-model qwen
  OK:    --prepare-ai qwen --agentic-model qwen
  ERRORE: --prepare-ai llama --agentic-model qwen
Con --prepare-ai all qualsiasi dei tre valori di --agentic-model e' incluso e quindi valido.

Eseguire subito un orchestrator dopo l'init:
python .\initScript.py --with-lab --run deterministic --mode balanced
python .\initScript.py --with-lab --run agentic --mode balanced
python .\initScript.py --with-lab --prepare-ai snap4city --run agentic --mode balanced
python .\initScript.py --with-lab --prepare-ai qwen --run agentic --mode balanced

Scelta del modello Agentic quando sono stati preparati tutti e tre:
python .\initScript.py --with-lab --prepare-ai all --agentic-model llama --run agentic --mode balanced
python .\initScript.py --with-lab --prepare-ai all --agentic-model qwen --run agentic --mode balanced
python .\initScript.py --with-lab --prepare-ai all --agentic-model snap4city --run agentic --mode balanced


Snap4City usa user_credentials.json. Se contiene ancora placeholder o manca e il terminale
e' interattivo, username/password vengono richiesti in console; la password non viene mostrata.

python .\initScript.py --commands-only

L'initializer installa o verifica gli scanner e aggiorna IDOR-Forge da
https://github.com/errorfiathck/IDOR-Forge.git in ~/.local/opt/idor-forge.
Le dipendenze upstream di IDOR-Forge restano nella .venv del repository.
Percorsi, interprete e launcher vengono salvati in .secops_runtime.json e
verificati dal preflight.

3. AGENTIC
----------
Modelli Agentic supportati (il provider viene scelto internamente):
  snap4city  -> Snap4City, endpoint llama4-agentic-inference
  llama      -> Ollama locale, llama3.1:8b
  qwen       -> Ollama locale, qwen2.5:7b

Non esiste un'opzione --ai-provider: --model sceglie l'AI e il codice deduce automaticamente
il provider corretto. Quindi snap4city usa Snap4City; llama e qwen usano Ollama.

I comandi Agentic stampati da initScript.py usano Snap4City per default e --require-ai.

Snap4City FAST (2 round):
python .\orchestratorAgentic.py --target <TARGET> --cookies "<COOKIE_HEADER>" --auth-only --authorized --model snap4city --max-rounds 2 --mode fast --require-ai

Snap4City BALANCED (2 round):
python .\orchestratorAgentic.py --target <TARGET> --cookies "<COOKIE_HEADER>" --auth-only --authorized --model snap4city --max-rounds 2 --mode balanced --require-ai

Snap4City DEEP (3 round):
python .\orchestratorAgentic.py --target <TARGET> --cookies "<COOKIE_HEADER>" --auth-only --authorized --model snap4city --max-rounds 3 --mode deep --require-ai

Alternative locali Ollama:
python .\orchestratorAgentic.py --target <TARGET> --cookies "<COOKIE_HEADER>" --auth-only --authorized --model llama --max-rounds 2 --mode balanced --require-ai
python .\orchestratorAgentic.py --target <TARGET> --cookies "<COOKIE_HEADER>" --auth-only --authorized --model qwen --max-rounds 2 --mode balanced --require-ai

Con seconda identità:
python .\orchestratorAgentic.py --target <TARGET> --cookies "<PRIMARY_COOKIE>" --secondary-cookies "<SECOND_ACCOUNT_COOKIE>" --auth-only --authorized --model snap4city --max-rounds 3 --mode deep --require-ai

Snap4City rispetta la priorita' del TokenManager del professore: prima riusa un access token ancora valido in token_stored.json;
se e' scaduto prova il refresh token; con credenziali reali in user_credentials.json usa username/password come ultimo passo normale.
Se user_credentials.json manca o contiene ancora placeholder, i placeholder non vengono mai inviati: vengono provati prima access token
e refresh token gia' salvati e solo se entrambi non sono utilizzabili, con terminale interattivo, vengono chiesti username/password
per quel processo. La password viene letta senza echo e le credenziali inserite non vengono scritte automaticamente nel JSON.

Senza --require-ai, se il planner AI fallisce può essere usato il piccolo fallback deterministico discovery-derived (massimo
3 azioni sicure per round). Con --require-ai il fallback del planner è disabilitato e il run fallisce se planning/analysis AI
non completano correttamente. Un fallimento di Ollama non passa automaticamente a Snap4City: per usare il provider remoto
si sceglie esplicitamente --model snap4city.

Il planner riceve candidati derivati dalla discovery e li seleziona in base al
valore informativo atteso. Può differire controlli ridondanti e non usa una
checklist minima. Ogni azione passa dagli stessi validator del Deterministic. Al termine, un nodo AI separato
rivaluta severity, descrizione, impatto e remediation dei finding usando soltanto l’evidenza
degli scanner; categoria, verification status ed evidenza non possono essere modificati.

6. PROFILI E OPZIONI
--------------------
fast      controllo rapido e budget ridotti
balanced  copertura ampia con priorità ai controlli importanti
deep      più target, richieste e budget per i controlli specialistici

Init: --with-lab --run --prepare-ai --agentic-model --snap4city-credentials --mode
      --skip-scanners --skip-preflight --skip-browser --require-browser --commands-only --version

--prepare-ai: all, snap4city, llama, qwen.
Se --prepare-ai e --agentic-model sono entrambi omessi, il valore effettivo e' all.
Se --prepare-ai e' omesso ma --agentic-model e' presente, il valore effettivo di preparazione diventa quel modello.
Con --with-lab e valore all vengono predisposti entrambi i modelli Ollama e verificato Snap4City.
Con snap4city l'initializer non provisiona ne' richiede Ollama se nessun modello locale e' richiesto.
Se --prepare-ai e --agentic-model sono entrambi presenti, all include qualunque modello; una selezione singola deve invece coincidere.

Per target remoti i workflow che inviano POST o file di prova richiedono anche
--allow-state-changes. Nel laboratorio locale autorizzato sono abilitati
automaticamente.
