SECOPS INITIALIZER - TECHNICAL GUIDE
====================================

Schematic reference of all commands and options of initScript.py and assessmentRunner.py.
Architecture, tool table, profiles/budgets, scope, and troubleshooting: see README.
Always aligned with the code: python <script> --help.

THERE ARE ONLY TWO CORE STEPS:
  1) initScript.py        -> prepares the environment (one time only).
  2) assessmentRunner.py  -> runs the assessment in the chosen mode (agentic or deterministic)
                             with the desired --config. This is the only step that repeats.
--dry-run and --auth-only are NOT steps of their own: only optional checks before step 2.

Requirements: Python 3.13 on a Debian VM, network to the authorized target, disk space.
Use only your own targets or ones you are explicitly authorized to test.


STEP 1 - INITIALIZATION
-----------------------

  python initScript.py              Installs/verifies environment, scanners, Chromium, preflight.
  python initScript.py --with-lab   Adds the local lab and prepares all supported AI backends.
  python initScript.py --commands-only   Prints this guide without installing anything.

  AI preparation with --with-lab:
    no selector                         Prepares all supported backends. Agentic defaults to Snap4City.
    --prepare-ai snap4city|llama|qwen   Restricts preparation to one backend. Snap4City is remote. llama/qwen use local Ollama.
    --snap4city-credentials FILE        Provider credentials (separate from the target).

  Do not use --skip-scanners or --skip-browser in a normal installation.


STEP 2 - ASSESSMENT
-------------------

  This is the only step that repeats: run assessmentRunner.py choosing mode and config.

  Agentic:        --orchestrator agentic --mode balanced --max-rounds 2 --require-ai --authorized
  Deterministic:  --orchestrator deterministic --mode balanced --authorized
  Direct target:  --target http://target --orchestrator agentic --mode balanced --authorized

  Optional check before the run (NOT a step of its own):
    --dry-run    validates config, scope, and jobs without launching scanners
    --auth-only  tests only login and session
    python assessmentRunner.py --config configs/dashboard-test.json \
      --orchestrator agentic --mode balanced --max-rounds 2 --require-ai --dry-run --authorized

CONFIGURATION
-------------

  cp configs/platform.example.json configs/my-target.json

  - Set authorization.confirmed=true only after real authorization.
  - Minimal fields: schema_version, platform.name, assets[] (id + service), execution.
  - Secrets via env (cookie_env/username_env/password_env), never in the JSON; link with credential_ref.

  Full example and authentication section: README.


PROFILES, RATE, AND TIME BUDGETS
-------------------------------

  execution.request_rate defaults to 10 request starts/s and accepts JSON integers from 1 to 50.
  Invalid values fall back to 10. The configured rate is a maximum, not a throughput target.
  The values below are base ceilings at the default rate of 10. Lower configured rates expand
  target-traffic-dependent budgets.

  Profile                    TEST       FAST       BALANCED    DEEP
  Planner nominal / round    5 min      6 h        30 h        48 h
  Planner nominal cumulative 5 min      12 h       60 h        144 h
  Operational execution      2 h        32 h       96 h        192 h
  Verification               10 min     60 min     120 min     240 min
  Final AI nominal reserve   20 min     4 h        12 h        24 h
  Reporting                  20 min     60 min     120 min     240 min
  Internal target/final guard 4 h       44 h       128 h       256 h
  Fixed parent cutoff        disabled   disabled   disabled    disabled

  Important per-action/tool timeouts at the default rate of 10:
  FFUF                       10 s       1 h        2 h         4 h
  Commix                     10 s       180 s      300 s       480 s
  Browser                    10 s       120 s      240 s       360 s
  Authorization              10 s       90 s       120 s       180 s

  These figures use the default round counts: TEST=1, FAST=2, BALANCED=2, DEEP=3. Planner
  cumulative and final-analysis values are nominal sizing/accounting values in normal mode, not
  aggregate wall-clock stop conditions. Measured planner/final-analysis control-plane time is
  excluded from the fixed target-work/finalization guard, and the assessment runner imposes no
  second fixed Agentic parent
  cutoff. Tool/provider calls remain individually bounded.

  FFUF uses the profile timeout as its global action budget. Its compact general phase may use the
  time remaining after earlier FFUF phases. Planner provider calls have a 20 s transport floor and
  BALANCED gives every started planner batch a full 1800 s (30 min) watchdog. Batch count never
  divides this timeout and normal mode has no aggregate planner wall-clock cutoff; splitting occurs
  only for real context overflow. Final AI analysis is also completion-driven: every BALANCED batch
  gets 1800 s, and every context/recovery split child gets a fresh full 1800 s allowance rather than
  sharing a shrinking parent deadline. A full-call timeout is therefore an AI/provider timeout, not
  a local stage-budget shortage. Scanner/verifier evidence is preserved if such a real AI error occurs.

initScript.py OPTIONS  (complete list)
--------------------------------------

  -h, --help                              Show help and exit.
  --with-lab                              Start/verify the local lab + ZAP, prepare the AI backends, create a session.
  --run none|deterministic|agentic        Run the DVWA assessment after init (deterministic/agentic require --with-lab).
  --prepare-ai all|snap4city|llama|qwen   AI backends prepared by --with-lab. If both AI selectors are omitted, all are prepared.
  --agentic-model snap4city|llama|qwen    Model used by --run agentic and the printed commands (if --prepare-ai is omitted, prepares only this one).
  --snap4city-credentials FILE            Snap4City provider credentials JSON (not the target account).
  --mode test|fast|balanced|deep          Coverage/runtime profile (default balanced; test = short budgets).
  --skip-preflight                        Skip the MCP/dependency preflight.
  --skip-scanners                         Skip scanner installation and do not require all of them.
  --skip-browser                          Do not install/verify Chromium; browser-only checks are skipped.
  --require-browser                       Compat: Chromium is already required by default (unless --skip-browser).
  --commands-only                         Print this guide, write init.txt, and exit.


assessmentRunner.py OPTIONS  (complete list)
--------------------------------------------

  Source (required, exactly one):
  --config FILE                           Multi-asset assessment from JSON.
  --target URL                            Direct HTTP/HTTPS target (alternative to --config).

  Identity (only with --target):
  --cookies HEADER                        Cookie header of the primary session.
  --secondary-cookies HEADER              Second authenticated identity (authorization/BOLA comparisons).

  Execution:
  --orchestrator agentic|deterministic    Chooses the path (overrides the config).
  --mode test|fast|balanced|deep          Coverage/runtime profile (overrides the config).
  --model snap4city|llama|qwen            Agentic AI backend (overrides the config).
  --max-rounds 1|2|3                      Maximum Agentic rounds. Extra rounds expand round-dependent budgets/watchdogs.
  --require-ai                            AI controls attack selection; no deterministic planner fallback is allowed.
                                           If AI control-plane work cannot complete, evidence is finalized with an explicit limitation instead of being discarded.
  --no-require-ai                         Allows the deterministic planner fallback if AI planning fails.
  --auth-only                             Runs only the authenticated profile.
  --dry-run                               Validates and saves the plan without executing scanners.
  --only JOB_ID                           Limit to a single service job (e.g. web01/https-main).
  --stop-on-error                         Stop after the first blocked job (a non-zero orchestrator exit is always fatal).

  Scope and authorization:
  --authorized                            Confirms authorization for non-local targets.
  --authorized-origin URL                 Adds an exact HTTP/HTTPS origin (repeatable).
  --allow-same-host-ports                 Authorizes HTTP/HTTPS on other ports of the exact same hostname.
  --no-allow-same-host-ports              Keeps exact-origin only (default when the config field is absent).
  --discover-same-host-services           Proactive same-host service discovery (requires --allow-same-host-ports).
  --no-discover-same-host-services        Disables same-host service discovery.
  --allow-state-changes                   Enables state-changing probes within safety and time limits.
  --no-allow-state-changes                Disables state-changing probes (including on local targets).


LOGS AND RESULTS
----------------

  Artifacts in reports/  (JSON = complete dataset, HTML = consultation, PDF = delivery summary).

  Logging a long run (use tmux on SSH):
    LOG="logs/balanced_$(date +%Y%m%d_%H%M%S).log"
    python assessmentRunner.py --config configs/dashboard-test.json \
      --orchestrator agentic --mode balanced --max-rounds 2 --require-ai --authorized > "$LOG" 2>&1
    tail -n 300 -F "$LOG"

  Download: scp debian@<host>:/home/debian/Cybersecurity_AgenticAI/reports/<file> .
