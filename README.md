# Agentic AI Pentesting & Reporting Automation System through MCP 

Automated web-application security assessment platform: one unified FastMCP Streamable HTTP
server (`servers/secopsServer.py`) imports the external-tool wrappers and project-specific checks
and exposes their tools through a single `/mcp` endpoint. Two orchestrators drive the same tool
catalogue against a target and produce PDF/HTML/JSON reports. Full command reference: `init.txt`.

## How core files works

### Initialization

- `initScript.py`: Installs/verifies dependencies, scanners, Docker images, Ollama and Playwright; with
`--with-lab` sets up the local training lab and ZAP; writes `.secops_runtime.json`, read by
preflight checks and both orchestrators. `--commands-only` (re)generates `init.txt`.

- `init.txt`: Operational cheat sheet, generated by `initScript.py --commands-only` — regenerate it
rather than hand-editing.

### Orchestrators

Then, there are mainly **2 orchestrators** that are responsible for directing the pipeline:

- `orchestratorDeterministic.py`: Fixed, reproducible LangGraph pipeline: discovery → broad scan → parameter scan →
authorization → browser/workflow → specialist checks → report. The baseline engine.

- `orchestratorAgentic.py`: Same discovery and validators as Deterministic, but an Ollama-driven planner selects
discovery-derived actions each round. After execution, a separate Ollama risk-assessment node can independently
enrich severity, description, impact and remediation while scanner evidence and confirmation status remain immutable.

The other files support the previous ones, as shared logic or support files.

## Requirements

- Python 3.12+
- Docker
- Ollama, only if you run Agentic mode without `--with-lab` (with `--with-lab`,
  Ollama runs automatically in its own Docker container)

## How to run 

Follow these steps:

1. General Init: Run a command from **step 1** of `init.txt`.
2. Orchestrator Choice: Run a **step 2 or 3** command from `init.txt`.

> [!IMPORTANT]
> After running step 1, if everything went well, the console will show the possible commands to run (corresponding to step 2), with any parameters already filled in.

`init.txt` also documents more targeted operations (steps 4-8): preflight/list-tools,
single-tool tests (ZAP, SQLMap, IDOR-Forge, JWT, Browser/Workflow/Authorization),
profile options, and Nuclei template updates.

## What is produced

If all steps are completed successfully, **3 files are produced**:

- JSON
- HTML
- PDF (obtained from the conversion and adaptation of HTML)

JSON is the complete, untruncated dataset (every deduplicated finding); HTML and PDF render a readable, size-capped subset of it for browsing.

Reports produced land in `reports/` .

## Common flags

- `--authorized` for any non-local target
- `--allow-state-changes` for state-changing probes on a remote target
